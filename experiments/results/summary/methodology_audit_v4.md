# Незалежний науковий аудит експериментального оцінювання MADE (V4.0)

**Тема магістерської роботи**: «Комп'ютерна система моніторингу потокових даних криптовалютної інфраструктури з модульним механізмом виявлення аномалій»  
**Спеціальність**: 123 «Комп'ютерна інженерія»  
**Дата аудиту**: 30 серпня 2026 року  
**Методологічна версія**: **4.0-scientific-audit**

---

## 1. Резюме аудиту (Executive Summary)

Проведено комплексний незалежний науковий аудит експериментального фреймворку системи **MADE** з позиції рецензента магістерської кваліфікаційної роботи за спеціальністю 123 «Комп'ютерна інженерія».

Головний висновок аудиту:
Усі вимірювані показники приведені у повну відповідність до фізичних та архітектурних процесів у комп'ютерній системі. Ліквідовано підміну понять між *обчислювальною швидкістю алгоритмів у пам'яті (Core Capacity)* та *наскрізною швидкістю стрімінгового комплексу з персистентністю (Live Pipeline Throughput)*. Розділено незрівнянні класи відмов і деталізовано складові затримок.

## 3. Реконструкція вимірювальних контурів (Data Flow & Measurement Points)

```text
[1. Генерація та інжекція]
  SyntheticMarketGenerator
    ↓ (Paced Timer: t_target = t_start + i / R_offered)
  Redis Streams (XADD 'events:normalized')
    [Фіксація: t_inj_start, t_inj_end, N_injected]

[2. Черга та транспортування]
  Redis Consumer Group ('made-core-processors')
    ↓ (PEL Buffer)
  MadeCoreWorker (claim_stale_messages / read_batch)

[3. Обробка ядром MADE Core]  <-- [L_core = 69.61 us (CPU in-memory)]
  NormalizedEventValidator       (L_val = 18.24 us)
    ↓
  DefaultContextEnricher         (L_enr = 12.15 us)
    ↓
  RuleEngineExecutor (4 модулі)  (L_rule = 24.82 us)
    ↓
  DefaultResultAggregator        (L_agg = 11.70 us)
    ↓
  DefaultPriorityEvaluator & DefaultAlertGenerator

[4. Персистентність та транзакції]
  PostgresStorageAdapter.persist_processing_result()
    ↓ (Асинхронний запис у PostgreSQL: processed_events, detections, alerts)
    [Фіксація: L_pipe = 3.42 ms (збереження підтверджено)]

[5. Підтвердження черги]
  Redis XACK (повідомлення вилучається з PEL)

[6. Зовнішня спостережуваність]
  FastAPI MadeQueryService (GET /api/v1/events/{id})
    [Фіксація: L_api = 18.47 ms, L_vis = 21.89 ms]
```

## 5. До переліку «Не змінювати» (Do Not Change List)

Під час аудиту суворо дотримано контракт недоторканності production-коду:
1. `NormalizedEvent`, `EnrichedEvent`, `DetectionResult`, `AggregatedResult`, `Alert` — без змін.
2. Алгоритми модулів `FuturesFuturesSpreadModule`, `SpotFuturesSpreadModule`, `DexFuturesSpreadModule`, `FundingSpreadModule` — без змін.
3. Формули розрахунку спредів $|P_1 - P_2| / P_{\text{ref}}$ та пороги детекції — без змін.
4. Схема та міграції бази даних PostgreSQL — без змін.

## 6. Залишкові методологічні обмеження (Remaining Limitations)

1. **Вузьке місце I/O**: Обмеження наскрізної швидкості комплексу на рівні 8–10 eps обумовлене послідовними транзакціями одного екземпляра воркера. Для збільшення пропускної здатності в промисловій експлуатації необхідне масштабування кількості воркерів у Consumer Group.
2. **Синтетичні дані**: Показники точності детекції (F1 = 1.0) підтверджують відсутність логічних помилок у програмній реалізації правил, але не замінюють дослідження поведінки на зашумлених ринкових даних з аномаліями ліквідності.
3. **Локальне середовище**: Затримки REST API вимірювалися на інтерфейсі loopback (localhost) і не включають затримок глобальних мереж (WAN latency).
